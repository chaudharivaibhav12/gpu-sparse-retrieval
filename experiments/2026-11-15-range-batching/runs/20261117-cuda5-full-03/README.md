# 20261117-cuda5-full-03

Completed. Full collection, 8,841,823 passages x 500 calibration queries, k=10, batch 1/4/16/32, range size 1024 (positions), 256 threads, modes sequential / streams / batched. RTX 4070 (cuda5, UUID `GPU-ab7b89ba-5664-fd05-e352-a4bc034e5ff7`), CUDA 12.6, `-arch=sm_89`, source `902278f`, protocol `configs/protocol.json` entry `full_collection` (registered and pushed before the first attempt). Inputs are the shared full-collection files pinned in `experiments/2026-11-15-full-collection-baselines/configs/protocol.json`, identified by SHA-256: GSP `e838dfbf...`, W1024 RBP `c7669620...`, queries `150917d7...`, CPU reference (top-10) `7a63bb52...`. The owner's copies on cuda5 are not readable by other accounts, so GSP and RBP were regenerated from the pinned raw CIFF (SHA-256 `16b111a4...`) with the unchanged importer and builder and accepted only because their whole-file hashes equal the pinned values; the CPU reference is the `full-top10.tsv` member of the published `20261115-cuda5-reference01` evidence archive. Stages, all from the timed source and binary on the timed GPU: build, kernel-body sync test, index verification, edge-case fixtures (864 driver runs, 8 guard rejections), three deliberate runtime-gate rejections, a `VERIFY=2` correctness run of all 12 configurations plus a partial-batch run (batch 7) per mode, then 3 timing processes per configuration (3 warm-up + 20 measured rounds, rotating order). Every correctness and timing process passed the runtime gate and its ranked answers equal the CPU reference (51 comparisons, zero mismatches). Two timing processes overlapped another user's process on the shared GPU and were kept under `raw/ineligible/` and replaced (`streams-b32-k10` and `sequential-b1-k10`, pass 1); the limit is three. No contended out-of-memory event occurred. Seeing no other process in the 0.25-second samples does not prove the GPU was exclusive. k=1000 was not run: there is no pinned full-collection top-1000 reference. This is the third recorded attempt; [20261117-cuda5-full-01](../20261117-cuda5-full-01/README.md) and [20261117-cuda5-full-02](../20261117-cuda5-full-02/README.md) stopped on the replacement limit and were never analysed. Raw per-query CSVs are stored as lossless `.gz`; uncompressed originals remain on the host's scratch (not backed up). Not recorded by the team runtime; self-recorded manifest.

Throughput is the median over 60 measured rounds (3 processes x 20) of 500 / (sum of the round's batch wall times). Ratios are paired by process and round (geometric mean, crossed bootstrap 95% interval, 10,000 draws, seed 20261117; with three processes the interval is a rough guide). Completion latency is measured from the start of the query's batch with complete batches; no batch-formation wait is included. "Tracked MB" is the device memory the driver allocates itself for the batched mode (10^6 bytes, checked by the runtime gate); "sampled MiB" is the largest 0.25-second `nvidia-smi` sample of the batched process. They are different quantities and neither is an exact peak.

The sequential control here (0.688 ms median completion at batch 1) is the same scorer, index and GPU as the parent single-query result (0.687415 ms), but a different driver, timing boundary and session; it is a consistency observation, not a contrast.
