# 20261116-cuda5-timing-02

Completed. Primary timing run. RTX 4070 (cuda5, UUID `GPU-ab7b89ba-5664-fd05-e352-a4bc034e5ff7`), CUDA 12.6, `-arch=sm_89`, source `8053d6f`, protocol `configs/protocol.json` as registered 2026-11-16. 1M passages (labelled scaling study, not the full collection) x 500 calibration queries, k=10 and k=1000, batch 1/4/16/32, range size 1024 (positions), 256 threads, modes sequential / streams / batched. Stages, all from the timed source and binary on the timed GPU: build, kernel-body sync test, index verification, edge-case fixtures (864 driver runs, 26,208 query checks, 8 guard rejections), three deliberate runtime-gate rejections (wrong mode, batch, threads), a `VERIFY=2` correctness run of all 24 configurations plus a partial-batch run (batch 7) per mode and k, then 3 timing processes per configuration (3 warm-up + 20 measured rounds, rotating order). Every correctness and timing process passed the expected-versus-actual runtime gate and its ranked answers equal the CPU oracle (102 comparisons, zero mismatches); answers are kept losslessly under `raw/answers/`. Raw per-query CSVs are stored as `.gz` (see `public_packaging` in the manifest); the `.gz` files are lossless and the uncompressed originals remain on the host's scratch (not backed up). Not recorded by the team runtime; self-recorded manifest. Three timing processes overlapped another user's process on the shared GPU, were marked ineligible, kept under `raw/ineligible/` and replaced (`sequential-b32-k1000` in pass 0, `batched-b4-k1000` twice in pass 2); this is exactly the registered limit of three. Seeing no other process in the 0.25-second samples does not prove the GPU was exclusive. This run follows [20261116-cuda5-timing-01](../20261116-cuda5-timing-01/README.md), which stopped on that limit and whose timings were never analysed.

Throughput is the median over 60 measured rounds (3 processes x 20) of 500 / (sum of the round's batch wall times). Ratios are paired by process and round (geometric mean, crossed bootstrap 95% interval, 10,000 draws, seed 20261117; with three processes the interval is a rough guide). Completion latency is measured from the start of the query's batch with complete batches; no batch-formation wait is included. "Tracked MB" is the device memory the driver allocates itself for the batched mode (10^6 bytes, checked by the runtime gate); "sampled MiB" is the largest 0.25-second `nvidia-smi` sample of the batched process. They are different quantities and neither is an exact peak.
